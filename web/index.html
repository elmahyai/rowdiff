Why not just use a text diff?

Line-based diff tools compare the third line to the third line. Real exports don't work that way: rows get inserted, deleted, re-sorted, and dates change. You end up with a wall of noise and no answer to the only question that matters — what actually changed for this record?

rowdiff joins the two files on a key column (an invoice number, SKU, email, account) and reports per-field changes. Numeric columns are compared with a tolerance so 2750.25 vs 2750.30 is a 0.05 drift you can allow — or not.

Typical jobs

  • Reconciling a bank statement export against your ledger.
  • Checking that last night's data migration changed only the rows it was supposed to.
  • Reviewing what an ERP or Shopify export actually changed week over week.
  • A CI check that fails the build when a fixture file drifts.

The command line version

Same engine, better for pipelines and big files. Zero dependencies, Node 18+.

npm install -g rowdiff

rowdiff before.csv after.csv --key invoice_id

# allow 1 cent of rounding drift, only fail on real changes
rowdiff before.csv after.csv -k invoice_id -t 0.01 --fail-on changed

# a self-contained HTML report you can email
rowdiff before.csv after.csv -k invoice_id -f html -o report.html

# GitHub Actions
- run: rowdiff before.csv after.csv -k invoice_id -f junit -o junit.xml

Exit code 0 means no differences, 1 means differences were found, 2 means a bad file or option. That is what makes it usable as a gate.

FAQ

Are my files uploaded?

No. This page is a single HTML file. The parsing and comparison run in your browser and the file contents never touch a network. You can also save the page and use it offline, or check the network tab: there are no requests after the page loads.

What is the "key column"?

The column that identifies a row — invoice_id, sku, email. Rows with the same key on both sides are compared field by field. Leave it empty to pair rows by position instead, which is what you want for two files with identical structure.

Does it handle European number formats?

Yes. €1.234,50 and €1,234.50 both parse to 1234.5 when "Read currency amounts" is on, and both separators are disambiguated by position.

How big can the files be?

The browser version holds both files in memory — comfortably fine into the low hundreds of thousands of rows. For very large files use the CLI, which is faster and can stream reports to disk.
